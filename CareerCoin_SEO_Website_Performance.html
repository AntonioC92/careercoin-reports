Render Blocking Requests
1 issue critico
80+ file CSS bloccano il rendering iniziale
Est. savings: 9,350 ms - Impatto su FCP e LCP
Critico
⚠ Problema
Il browser deve scaricare e processare oltre 80 fogli di stile CSS prima di poter disegnare qualsiasi cosa sullo schermo. Questo blocca il rendering per 9.35 secondi su rete 4G lenta. Tra i file più pesanti:
  • buddypress.css - 104 KiB
  • buddypress.min.css - 93 KiB
  • widget-styles.css - 47 KiB
  • theme.css - 43 KiB
  • learndash.css - 39 KiB

Molti di questi CSS appartengono a plugin attivi ma non utilizzati sulla homepage (LearnDash, GamiPress, WooCommerce, BuddyZoom, BP Polls ecc). Inoltre iubenda carica 3 script di consenso nella critical path aggiungendo ulteriori ~5 secondi.

✓ Soluzione Proposta
  • Attivare WP Rocket → Remove Unused CSS (Safe Mode): genera automaticamente fogli di stile specifici per ogni pagina rimuovendo tutto il CSS non necessario
  • Verificare quali plugin caricano CSS globalmente e limitare l'enqueue alle sole pagine dove il plugin è effettivamente usato (tramite filtro wp_enqueue_scripts)
  • Aggiungere preconnect a cdn.iubenda.com nell'<head> - PSI stima 300ms di risparmio LCP solo da questa modifica
  • Configurare WP Rocket per escludere GTM e iubenda dal delay (già identificato nel Progetto 1 ma non ancora implementato)

Immagine LCP mal configurata
2 issue critici
L'immagine principale ha lazy loading abilitato
LCP element: img.attachment-full - resource load delay: 2,760ms
Critico
⚠ Problema
L'immagine hero della homepage - che è l'elemento LCP (Largest Contentful Paint), cioè il contenuto visivo più grande above the fold - ha il lazy loading applicato. Questo significa che il browser aspetta a scaricarla, ritardando il suo rendering di 2,760ms aggiuntivi. L'effetto opposto di quello desiderato.

In più manca fetchpriority="high", che segnalerebbe al browser di scaricare questo asset prima di tutti gli altri.

L'immagine viene servita a 768×446px ma è displayata a 368×214px: occcupa il doppio dello spazio necessario per niente.
✓ Soluzione Proposta
  • Nell'impostazione dell'immagine Elementor, disattivare il lazy load per l'immagine hero - Elementor ha l'opzione per escludere singoli elementi
  • Aggiungere fetchpriority="high" all'immagine hero tramite filtro WordPress o manualmente nel template
  • Creare una versione dell'immagine a dimensioni corrette (400×232px circa) e servirla sulla homepage invece del full-size - risparmio stimato 34 KiB
  • Convertire l'immagine in formato WebP se non già fatto

Importante
⚠ Problema
Lighthouse non riesce a scaricare il file robots.txt di careercoin.io. Se il file è malformato o restituisce un errore, i crawler di Google non sanno come indicizzare il sito correttamente. Questo può bloccare o rallentare l'indicizzazione di nuove pagine e impatta il punteggio SEO (85 invece di potenziale 100+).
✓ Soluzione Proposta
  • Verificare che careercoin.io/robots.txt esista e risponda con HTTP 200
  • Se non esiste, crearlo con il plugin Yoast SEO o Rank Math (già attivo sul sito?)
  • Validarlo con il Google Search Console URL Inspection Tool
  • Minimo necessario: User-agent: * / Allow: / / Sitemap: https://careercoin.io/sitemap.xml
